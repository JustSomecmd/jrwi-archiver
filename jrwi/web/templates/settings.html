Once TubeArchivist has downloaded the YouTube version, the archiver can delete its own copy, and the episode plays from TubeArchivist like the other YouTube episodes. Podcast feed

The site's private podcast feed, the address it gives you for podcast apps. It lists the audio posts, so it adds no new content, but it says the time of day each episode came out (the site only shows the date), and reading it is one small request without logging in. So it's read every few minutes between checks, and when a new episode shows up in it, a check of the site starts. What it holds is on the Admin page.

It holds a key that's yours, like a password, so it's never shown again once saved.
0 never reads it.

Transcripts

Many episodes link a transcript (a Google Doc saved as a PDF). The archive reads it into lines, speaker by speaker, so the web app and the apps can show it. Timing it hears the episode once with a speech recognizer (faster-whisper) and matches the transcript's words to what it heard, so the line being spoken can be shown as it plays. That takes a while and a fair amount of memory, so it runs between checks, one episode at a time, at a low priority, and a check always goes first. Try one episode from the Admin page before setting when it runs.

The server's local time (TZ in the compose file). The hours can go past midnight. An episode that's half heard when they end is kept, and carries on the next day.
As soon as there's something new: after each check that finds new episodes, until every transcript is timed. Time transcripts now on the Admin page does the same once, whatever is chosen here.
The speech model is downloaded once, the first time (to the data folder's models). The Admin page shows how long the last episode took and the most memory it used.
0 uses half of them, at most 8, leaving the rest for Jellyfin and the others.
