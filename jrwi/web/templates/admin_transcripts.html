What the figures mean

Words found: the share of the transcript's words found, in order, in what the speech model heard. The lines' times rest on these, so it's how well the two agree; under 30% means the transcript isn't this episode's, and it isn't timed. It doesn't check the times themselves: on test episodes with a known answer, 90% of lines started within 0.7 seconds of it.

Lines placed: lines that got a time from words of their own. The rest sit right after the line before them, or, next to a long gap, show untimed. The figure in colour before each timed episode is its share of lines placed: deep purple at 40% and under, turning through pink and orange to yellow at 95% and over.

Hearing: how long hearing the episode took, added up over pauses, without loading the model. Speed is the episode's length over that: 6× is an hour of sound in 10 minutes.

Memory: the most the speech model's process used. Threads lists each number it ran with, when the setting changed while it ran.

Hearing on your PC

A faster computer can do the slow part, hearing the episodes, and send back what it heard. The archiver still matches it to the transcript, so the lines come out the same way, and each try is in the record above, marked PC. With an NVIDIA graphics card it's many times faster.

  1. Install Python, then in a terminal: pip install faster-whisper psutil. For an NVIDIA graphics card also: pip install nvidia-cublas-cu12 "nvidia-cudnn-cu12==9.*"
  2. {{ icon('download') }} Download the PC program into a folder of its own.
  3. Run python jrwi_hear.py setup there: the archiver's address and its API token, from Settings. Then python jrwi_hear.py check says whether it reached the archiver and can use the graphics card.
  4. python jrwi_hear.py compare 123 456 hears those episodes (the number at the end of an episode's address) with medium.en, large-v3-turbo and large-v3, sends each and compares them; --models picks others.
  5. python jrwi_hear.py run --all --models medium.en hears every episode with a transcript, timed or not, one after another, skipping those that model has heard already, so it carries on where it stopped. Without --all only those not timed yet. The timing in use stays when it found more of the transcript's words than the new one.
  6. To try an episode that went badly again, take its post number from the list above (sort by lines placed) and hear it with another model: python jrwi_hear.py compare 123 --models large-v3,medium.en. The same model again hears it the same way, so it would find the same words.

Without the network: Export for your PC on an episode's admin page gives a file with its sound; python jrwi_hear.py file jrwi-job-123.zip writes a result file next to it, to bring back with Import from your PC on the same page.
